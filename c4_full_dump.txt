[218] (normal) 4.1.1. Hệ thống Type System, Nullable Reference Types và Encapsulation 
[219] (normal) C# là một ngôn ngữ định kiểu tĩnh mạnh (Strongly-typed, Object-Oriented Programming). Trong Common Language Runtime (CLR), hệ thống kiểu dữ liệu được phân chia thành hai nhóm cơ bản với mô hình quản lý bộ nhớ hoàn toàn khác biệt:
[220] (normal) • Value Types (Kiểu giá trị): Bao gồm các kiểu nguyên thủy (int, long, decimal, bool, enum) và struct. Dữ liệu của Value Type được lưu trữ trực tiếp trên ngăn xếp (Stack) hoặc nhúng trực tiếp trong đối tượng chứa nó. Việc gán giá trị thực hiện sao chép toàn bộ nội dung (Copy by value).
[221] (normal) • Reference Types (Kiểu tham chiếu): Bao gồm class, interface, delegate và string. Đối tượng thực sự được cấp phát trên bộ nhớ Heap và được quản lý tự động bởi Garbage Collector (GC). Biến của Reference Type chỉ lưu giữ địa chỉ tham chiếu (Memory Pointer) trỏ tới vùng nhớ trên Heap.
[222] (normal) Một bước tiến mang tính cách mạng từ C# 8.0 và được hoàn thiện trong C# 12 là tính năng Nullable Reference Types (NRT), được bật mặc định trong PropNest qua thẻ '<Nullable>enable</Nullable>'. Trước đây, mọi biến Reference Type đều có thể nhận giá trị null, dẫn đến lỗi 'NullReferenceException' kinh điển trong lập trình. Với NRT, trình biên dịch Roslyn phân biệt tường minh:
[223] (normal) • Non-nullable Reference Type (ví dụ: string Title): Trình biên dịch bắt buộc phải có giá trị, nếu gán null hoặc không khởi tạo sẽ lập tức cảnh báo lúc biên dịch.
[224] (normal) • Nullable Reference Type (ví dụ: string? Description): Cho phép nhận null nhưng bắt buộc lập trình viên phải kiểm tra null trước khi truy cập.
[225] (normal) Về tính đóng gói (Encapsulation) trong Lập trình Hướng đối tượng (OOP): Một thiết kế chuẩn mực phải ngăn chặn việc tùy tiện thay đổi trạng thái nội bộ của đối tượng từ bên ngoài (Anemic Domain Model). Thay vào đó, toàn bộ thuộc tính phải dùng 'private set', và mọi sự biến động trạng thái chỉ được thực hiện thông qua các Domain Method có thẩm định nghiệp vụ.

[230] (normal) 4.1.2. Tính bất biến với Record Types và cú pháp C# 12 (Primary Constructors, Collection Expressions) 
[231] (normal) Trong phát triển phần mềm hiện đại, tính bất biến (Immutability) là nguyên tắc cốt lõi giúp mã nguồn an toàn trong môi trường đa luồng (Thread-safe) và loại bỏ hoàn toàn các lỗi 'tác dụng phụ' (Side-effects) ngoài ý muốn.
[232] (normal) C# 9.0 giới thiệu từ khóa 'record', và C# 10/12 tiếp tục hoàn thiện thành 'record class' và 'record struct'. Khác biệt cơ bản giữa 'class' truyền thống và 'record' nằm ở cơ chế so sánh bằng:
[233] (normal) • Class truyền thống dùng Reference Equality: Hai đối tượng class dù có toàn bộ thuộc tính giống hệt nhau nhưng nằm ở hai ô nhớ khác nhau thì toán tử '==' vẫn trả về false.
[234] (normal) • Record dùng Value Equality: Trình biên dịch tự động sinh hàm Equals(), GetHashCode() và toán tử '==' dựa trên giá trị của tất cả các thuộc tính bên trong. Nếu hai record có dữ liệu giống nhau, chúng được coi là bằng nhau.
[235] (normal) Hai cải tiến cú pháp đột phá của C# 12 được dự án PropNest khai thác tối đa gồm:
[236] (normal) • Primary Constructors: Cho phép khai báo tham số khởi tạo trực tiếp trên tên class hoặc record. Trình biên dịch tự động tạo các trường dữ liệu tương ứng, giúp loại bỏ hoàn toàn mã thừa gán tham số trong constructor truyền thống.
[237] (normal) • Collection Expressions: Cú pháp tạo mảng và danh sách đồng nhất thông qua cặp ngoặc vuông '[..]', thay thế cú pháp rườm rà 'new List<T>()' hay 'new T[] { ... }', đồng thời cho phép gộp các tập hợp bằng toán tử spread '..'.

[241] (normal) 4.1.3. Pattern Matching và Switch Expressions 
[242] (normal) Pattern Matching (Khớp mẫu) là một trong những tính năng mạnh mẽ nhất của C# hiện đại, cho phép kiểm tra hình dạng (Shape) và kiểu dữ liệu của đối tượng một cách ngắn gọn, an toàn và trực quan.
[243] (normal) Thay vì sử dụng câu lệnh 'switch-case' cồng kềnh với các từ khóa 'break' và biến tạm như trong C/C++ truyền thống, C# 8+ cung cấp Switch Expression biến câu lệnh rẽ nhánh thành một biểu thức tính toán trả về giá trị (Expression-bodied):
[244] (normal) • Type Pattern: Kiểm tra xem đối tượng có thuộc một kiểu cụ thể hay không (ví dụ: 'KeyNotFoundException => 404').
[245] (normal) • Property Pattern: Kiểm tra giá trị các thuộc tính bên trong đối tượng mà không cần ép kiểu thủ công.
[246] (normal) • Discard Pattern (_): Đại diện cho trường hợp mặc định (Default/Fallback case) khi không có mẫu nào khớp.

[249] (normal) 4.1.4. Lập trình bất đồng bộ (Asynchronous Programming) với async/await, Task, ValueTask và CancellationToken
[250] (normal) Trong các ứng dụng Web Backend có lưu lượng truy cập cao, các tác vụ I/O (truy vấn Database, đọc ghi ổ đĩa, gọi HTTP API bên ngoài) chiếm phần lớn thời gian xử lý. Nếu sử dụng lập trình đồng bộ (Synchronous), luồng thực thi (Thread) của máy chủ sẽ bị phong tỏa (Blocked) trong trạng thái chờ đợi, dẫn đến cạn kiệt Thread Pool (Thread Pool Starvation) và làm sập hệ thống.
[251] (normal) ASP.NET Core giải quyết triệt để bài toán này bằng mô hình Task-based Asynchronous Pattern (TAP) thông qua cặp từ khóa 'async' và 'await':
[252] (normal) Cơ chế State Machine ngầm định: Khi gặp từ khóa 'await', trình biên dịch C# tự động tách phương thức thành một Máy trạng thái (State Machine). Luồng hiện tại được giải phóng ngay lập tức để quay về Thread Pool phục vụ các HTTP Request khác. Khi thao tác I/O hoàn tất (I/O Completion Port thông báo), Thread Pool sẽ cấp một luồng bất kỳ để tiếp tục thực thi phần mã phía sau.
[253] (normal) Phân biệt Task và ValueTask: 'Task<T>' là một đối tượng Reference Type được cấp phát trên Heap. Nếu một phương thức bất đồng bộ thường xuyên trả về kết quả có sẵn (cached/synchronous completion), việc tạo Task liên tục sẽ gây áp lực lớn lên Garbage Collector. '.NET' giới thiệu 'ValueTask<T>' là một struct nằm trên Stack. Trong Entity Framework Core 8, phương thức AddAsync trả về ValueTask, do đó cần gọi '.AsTask()' nếu interface yêu cầu Task.
[254] (normal) Cơ chế ngắt lan truyền với CancellationToken: CancellationToken là cơ chế cộng tác ngắt tác vụ (Cooperative Cancellation). Khi người dùng hủy request hoặc đóng trình duyệt, HTTP connection bị ngắt, CancellationToken kích hoạt trạng thái hủy. Việc truyền CancellationToken xuyên suốt qua các tầng (Controller -> Service -> Repository -> DbContext) giúp hệ thống ngừng ngay lập tức các câu lệnh SQL tốn kém, tiết kiệm tối đa tài nguyên máy chủ (quy tắc CA2016).

[271] (normal) 4.2.1. Kestrel Web Server và cơ chế xử lý I/O bất đồng bộ 
[272] (normal)  Kestrel là máy chủ web (Web Server) tích hợp sẵn trong nhân của ASP.NET Core, được thiết kế từ đầu với tiêu chí hiệu năng cao, đa nền tảng (chạy trên Windows, Linux, macOS) và tối ưu hóa tài nguyên phần cứng. Về mặt kiến trúc mạng, Kestrel hoạt động theo mô hình:
[273] (normal) • Lớp Socket Transport: Sử dụng trực tiếp Socket API của hệ điều hành kết hợp với kỹ thuật I/O đa luồng bất đồng bộ (I/O Completion Ports trên Windows hoặc epoll trên Linux) để tiếp nhận hàng chục nghìn kết nối mạng đồng thời mà không tạo luồng xử lý riêng cho từng socket.
[274] (normal) • Hỗ trợ đa giao thức: Kestrel hỗ trợ hoàn chỉnh HTTP/1.1 (truyền tải dạng văn bản), HTTP/2 (ghép kênh đa luồng Multiplexing trên cùng một kết nối TCP), và HTTP/3 (chạy trên giao thức UDP/QUIC giúp giảm độ trễ bắt tay mạng).
[275] (normal) • Vòng đời đối tượng HttpContext: Khi một HTTP Request được gửi đến, Kestrel phân tích các byte dữ liệu nhị phân thô từ socket thành đối tượng HttpContext. Đối tượng này đại diện cho toàn bộ thông tin của phiên giao dịch: HttpContext.Request (Headers, Body, Query, Path), HttpContext.Response (StatusCode, Headers, BodyStream) và HttpContext.User (danh tính ClaimsPrincipal sau khi xác thực).

[288] (normal) 4.3.1. Nguyên lý Inversion of Control (IoC) và Dependency Inversion (SOLID) 
[289] (normal) Inversion of Control (IoC - Đảo ngược điều khiển) là nguyên lý thiết kế phần mềm trong đó quyền kiểm soát luồng thực thi và việc khởi tạo các đối tượng phụ thuộc được chuyển giao từ lớp tiêu thụ sang một Framework điều khiển trung tâm.
[290] (normal) Dependency Inversion Principle (DIP - Chữ D trong nguyên lý thiết kế SOLID) quy định rõ:
[291] (normal) • 1. Các module cấp cao (như ListingService) không được phụ thuộc trực tiếp vào các module cấp thấp (như ListingRepository hay SQL Server). Cả hai bắt buộc phải phụ thuộc vào Abstraction (Interface IListingRepository).

[293] (normal) Nhờ có IoC Container trong .NET (Microsoft.Extensions.DependencyInjection), ListingService không bao giờ dùng từ khóa 'new ListingRepository()', mà chỉ khai báo Interface trong constructor. [332] (normal) 4.5.1. Attribute Routing, Route Constraints và Model Binding
[333] (normal) Trong ASP.NET Core Web API, Controller là lớp đón nhận và phản hồi các HTTP Request. Hệ thống định tuyến Attribute Routing cung cấp khả năng gán trực tiếp URL template lên lớp Controller và từng Action:
[334] (normal) • [ApiController]: Thuộc tính bắt buộc, kích hoạt các hành vi tự động: tự động thẩm định dữ liệu đầu vào (Model Validation) và trả về 400 Bad Request nếu dữ liệu lỗi; tự động suy luận nguồn dữ liệu binding ([FromBody], [FromQuery]); chuẩn hóa lỗi theo ProblemDetails.
[335] (normal) • [Route("api/v1/listings")]: Định nghĩa tiền tố đường dẫn RESTful cơ sở, hỗ trợ phân phiên bản API (API Versioning).
[336] (normal) • Route Constraints: Ký pháp '{listingId:long}' áp đặt ràng buộc kiểu số nguyên 64-bit lên đường dẫn. [337] (normal) • Model Binding: Quá trình tự động ánh xạ dữ liệu từ HTTP Request (JSON Body, Route Parameters, Query String, Headers) sang các đối tượng tham số C# (DTOs).
